## 3. 已吸收或已实现的功能

### 3.1 Agent 能力与上下文治理

- **可信联网检索（Tavily）**：增加政府、学术和通用检索路径，按本轮生成独立检索 trace，清理模型仓库/专利等不符合学术检索约束的来源，并在缺少联网密钥时给出可控降级。
- **上下文与持久化脱敏**：会话持久化对命令、路径、附件引用、凭据、精确空间字段和工具输出做过滤；历史预览优先使用安全的用户消息摘要。
- **附件外发授权门闩**：影像发送给外部模型需要本轮显式授权；GeoTIFF 对外发送前转为受限 PNG，避免直接暴露原始空间元数据。
- **会话存储增强**：支持空会话隐藏、无显示数量上限的历史查询、会话删除后的下一个会话选择，以及删除最后一个会话时创建新会话并回到对话视图。

主要提交：`7dc54b3`、`afff61c`；主要文件：`TF-agent/agent.py`、`TF-agent/agent_context_policy.py`、`TF-agent/conversation_store.py`。

### 3.2 地图、AOI 与 GEE 工作流

- **地图定位时序稳定**：新定位命令会取消旧命令的延迟重试，避免旧指令覆盖最新定位；通过 ACK 状态判断地图是否真正完成定位。
- **AOI 绘制预览与同步反馈**：点选、矩形和多边形交互保留实时预览，只有满足最小几何条件才提交，提交后显示同步成功或失败状态。
- **地图/状态区联动布局**：状态与系统日志放在地图下方，使用边界拖动条调节高度；聊天面板宽度变化时状态区边界同步更新；收起/展开状态通过边界三角按钮控制。
- **GEE 计划阶段无副作用**：计划阶段不再写入本地工作目录；失效资产记录允许重新登记，减少重试时的脏状态。

主要提交：`21ce1f4`、`bdb9abb`、`2e64374`、`795cdbb`；主要文件：`TF-agent/app.py`、`TF-agent/globe_engine.py`、`TF-agent/gee_agent_loop.py`。

### 3.3 聊天 UI 与附件交互

- **发送区布局**：固定为 `＋附件 → 输入框 → 发送` 同一行；原生上传器隐藏，仅保留加号入口。
- **附件预览**：支持 PNG/JPG/WebP/TIFF，多文件横向排列并在发送框内滚动；加号悬浮提示保持固定，不显示文件名；发送后通过 uploader epoch 和清空标记清理预览，避免下一轮继承上一轮文件。
- **重复/闪烁控制**：附件身份去重、聚合 `DataTransfer`、预览签名幂等渲染，避免同一文件重复发送、预览叠放或闪烁。
- **消息卡片**：用户消息靠右、Agent 消息靠左，卡片按内容收缩并受最大宽度约束。
- **历史页**：历史视图仅承担会话导航，不显示聊天消息和发送框；会话列表填充剩余空间，超出后在列表内部滚动，不限制显示条数。
- **异常通知**：错误/警告采用可关闭的浮动通知，不再通过插入大块内容挤压地图和 Agent。
- **响应式与拖动边界**：状态区和 Agent 面板使用边缘命中区域；去除外层白边和多余边框，保留蓝色拖动条；补充 iframe/父文档事件绑定和 Streamlit 重渲染后的重新绑定。

主要提交：`afff61c`、`f18936a`、`e876e25`、`7ca457c`、`994ae9f`；主要文件：`TF-agent/app.py`、`tests/unit/test_chat_ui_contract.py`、`tests/browser/test_streamlit_ui.py`。

## 5. 明确作为 bug 保留的项目

### BUG-MODEL-001：文本模型与视觉模型未真正分离

这是本报告最重要的未完成项，按用户要求不计入吸收成功：

- 当前 `.env` 使用 `QWEN_CHAT_MODEL=qwen3.8-27b`；
- `TF-agent/llm_backend.py` 已有能力声明和 `require_vision` 参数，但 DashScope 能力仍主要由模型名中的 `vl` 推断；
- `TF-agent/agent.py` 仍通过单一 `_backend_config` 构造工具 Agent，`_get_agent_executor()` 没有按视觉能力选择独立模型；
- `chat_with_vlm()` 将图片转换为 `image_url` 后交给同一 Agent/文本后端路径。因此当前模型若恰好支持多模态，能够识别截图，但架构上没有“文本模型 + 视觉模型”的明确路由、能力校验、失败降级和配置隔离。

建议后续以兼容当前截图识别为前提，增加独立的 `text_backend`/`vision_backend` 配置和显式能力探测；文本工具调用继续走文本模型，存在附件时才路由到视觉模型，并对视觉模型不可用提供不改变地图/手动任务的降级提示。

## 6. 旧审查中仍需复核的风险

以下问题来自早期功能审查或架构证据，当前报告没有把它们标成已修复，也没有把会话用户/网关归属隔离列入范围：

1. 工作流最终批准、`approved_spec_hash`/revision 的全链路重验是否覆盖所有执行入口。
2. 取消任务后迟到的异步成功回调是否可能重新写入完成状态。
3. 不同 Job 之间的重型资源锁、输出目录和 GEE 配额是否真正全局互斥。
4. 进程重启后的 DAG、批准参数、资产 lineage 和执行账本是否可完整恢复。
5. 状态区收起时后台任务是否仍持续更新，重新展开后是否能恢复最新快照。
6. 附件文件名、GeoTIFF 元数据和外发授权在真实远程模型请求中的最小暴露范围。
7. `need_report`、报告产物 lineage 和外部验证结果是否已接入生产工作流，而不只是测试/计划文件。

这些条目需要单独的工作流、并发、故障注入和真实服务验收，不能用本次 117 个定向测试代替。
